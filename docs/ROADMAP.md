# 迭代计划（ROADMAP）

> 本文只记**版本节奏**和**已经做完 / 明确不做**的决定。
> 还没做的事一律记在 [`BACKLOG.md`](BACKLOG.md)；技术细节在 [`TECH_PLAN.md`](TECH_PLAN.md)。

## 版本号规则

- **1.0** = 首个完整可玩版本
- **1.1** = 技术方案收尾（护体规则 / 调试面板 / 种子复现），不加新内容
- 之后**每完成一轮迭代 +0.1**：1.2、1.3……
- 唯一真值在 `src/data/version.js`，`index.html` 的 `<title>` 和 `?v=` 查询串跟着改（`test/smoke.mjs` 第 26 组会拦）

> 为什么以前会分裂成 0.7.0 / 0.16.0：`<title>` 写的是项目版本，`?v=` 写的是"AI 做完的需求编号"。
> 两个数字各说各话，看截图根本判断不出跑的是哪一版。以后版本只跟迭代走，**不再跟需求编号走**。

## 1.1（2026-10-26）

| 事项 | 结果 |
|---|---|
| 受伤优先级漏洞 | 新建 `game/guard.js`：护盾/荆棘/技能护体**同一时刻只生效一个**。原来能叠出 28 秒免伤，现在最多 13 秒 |
| 调试面板 | `ui/debug.js`：`?debug=1` 看 FPS/实体/阶段/血量系数/seed，F1 跳波、F2 升级、F3 无敌、F4 清屏 |
| 种子复现 | `?seed=12345` 固定随机数，面板显示本局真实 seed；测试断言"同 seed 刷怪序列逐项相同" |
| 荆棘改版 | 按次数消耗（4 层），**每挡一次给 1 秒无敌**；三角范围放大（环半径 ×1.45、边长 ×1.2）、伤害 2 → 4 |
| 顺带修 | 技能护体原来借 `invincible = 780`，导致整段 13 秒技能都在播受击姿势并闪烁。已拆成独立 `skillGuard` |

## 1.0（2026-10-25）

首个完整可玩版本。收尾时补掉两条 P0：

| 事项 | 结果 |
|---|---|
| 加载界面形同虚设 | `gfx/preload.js`：图片没就位不撤加载层，带进度、单张 12 秒超时。启动顺序改为「读档 → 建输入 → 等图片 → 开循环 → 撤加载层」 |

## 已关闭（不做）

| 事项 | 决定 | 理由 |
|---|---|---|
| 移动端适配 | **不做** | 游戏定位桌面键鼠。竖屏 390×844 下画面只剩中间 292px、字号约 7px，为不存在的场景花时间是纯亏 |
| 真人试玩验证 | **已满足** | 用户本人已完整体验，视为通过。后续不要再把"没人试玩过"当风险项提 |
| 角色阵容扩展（向晚、珈乐） | **不优先** | "不必关心有哪些人玩"——现有 3 人够撑起当前版本，扩阵容不解决核心问题 |
| 减少闪光无障碍开关 | **不做** | 用户明确说不需要。震屏另算，它的顾虑是手感过冲，不是无障碍 |

## 记账方式

1. 每轮迭代开始：从 `BACKLOG.md` 里挑，挑中的在 BACKLOG 里标一句"→ 1.2"，别偷偷加塞。
2. 每轮迭代结束：在本文加一节，写清"改了什么、为什么"；BACKLOG 里对应行删掉。
3. **版本一升，`BACKLOG.md` 里"已知但不打算改"的内容要跟着复查一遍**，别让它们躺着变成谎言。
